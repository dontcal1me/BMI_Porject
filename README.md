## 🧩 4. 모듈 설계

| 모듈 | 담당 영역 | 세부 내용 |
|------|-----------|-----------|
| **모듈 1**<br>`health_db.py`<br>(데이터 & 저장소) | 데이터 구조화 및 파일 영구 저장 | • 레코드 모델링: 식별번호, 이름, 생년, 성별, 키, 몸무게, BMI, 비만도 상태를 담는 객체 구조 및 딕셔너리 변환(`to_dict`) 지원<br>• 식별번호 자동 생성: 신규 레코드 추가 시 고유한 환자식별번호 발급<br>• 다중 파일 I/O: JSON, CSV, TXT, Pickle 포맷별 저장(save) 및 로드(load)<br>• 예외 처리: 파일 부재나 손상 시 `try-except` 처리 |

| **모듈 3**<br>`health_gui.py`<br>(사용자 인터페이스) | GUI 시각화 및 이벤트 연동 | • 화면 레이아웃: 입력 폼(Entry), 버튼, 파일 형식 선택 위젯 등<br>• 표 시각화(Treeview): 건강 정보를 엑셀 표 격자 형태로 출력, 스크롤바 연동<br>• 이벤트 바인딩: 행 클릭 시 입력창에 자동 입력(`<<TreeviewSelect>>`)<br>• 로직 호출 및 피드백: 모듈 2 메서드 호출, 성공/실패를 messagebox로 안내 |

### BMI 계산 공식

```
BMI = 몸무게(kg) / (키(cm) / 100)²
```

결과는 소수점 둘째 자리에서 반올림하며, 비만도 상태는 **저체중 / 정상 / 과체중 / 비만** 으로 판정합니다.

## ✅ 5. 기능 요구사항

### FR-01. 건강정보 등록
- **신규 레코드 추가 (UI 입력)**: GUI 화면에서 사람 정보와 건강 정보를 직접 입력받아 등록
- **중복 체크**: 이미 존재하는 데이터(식별번호 또는 중복된 개인 정보)가 있는지 검사하여 중복 등록 방지
- **환자식별번호 자동 생성**: 고유한 식별번호(ID)를 시스템 내부 로직으로 자동 발급
- **(선택) 엑셀 파일 일괄 등록**: 외부 엑셀 파일(CSV 등)을 업로드하여 여러 명의 건강 정보를 한 번에 추가

### FR-02. 건강정보 조회 및 검색 (목록, 개인)
- **전체 목록 보기**: 등록된 전체 사용자의 건강 정보를 엑셀 표(격자) 형태로 조회
- **상세 검색하기**: 이름, 식별번호, 특정 조건(BMI 상태 등)으로 검색하여 상세 조회

### FR-03. 건강정보 수정
- **개인별 정보 갱신**: 특정 사람을 선택하여 키, 몸무게, 추가 건강 정보 등을 수정하고 즉시 반영
- **BMI 자동 재계산**: 키나 몸무게 변경 시 BMI 수치와 비만도 판정 결과 자동 재계산

### FR-04. 건강정보 삭제
- **레코드 제거**: 특정 사람의 건강 정보 및 사람 정보를 선택하여 목록 및 영구 저장소에서 삭제

### FR-05. 건강정보 통계
- **통계 정보 산출**: 총 인원수, 평균 키, 평균 몸무게, 평균 BMI 등 요약 통계를 연산하여 화면에 시각화

## 🔒 7. 비기능 요구사항

### 1) 예외 및 오류 처리 (Robustness & Error Handling)
- 키·체중에 문자열 또는 0 이하의 값을 입력해도 프로그램이 비정상 종료되지 않음
- 잘못된 값 입력 시 messagebox로 올바른 숫자 입력을 유도하는 경고 메시지 출력
- 파일 입출력 시 권한 문제, 디스크 용량 부족, 파일 손상 등이 발생해도 `try-except`로 처리하고 기본값(빈 리스트 등) 반환

### 2) 사용성 및 사용자 경험 (Usability)
- 추가·수정·삭제·저장 성공 시 알림 팝업(`messagebox.showinfo`) 제공
- 표(Treeview)의 행을 클릭하면 입력 폼이 자동으로 채워져 바로 수정·삭제 가능

### 3) 코드 품질 및 유지보수성 (Maintainability & OOP)
- **역할과 책임의 분리(SoC)**: `health_db.py` / `health_logic.py` / `health_gui.py` 독립 모듈로 분리
- **객체지향 설계**: 반복되는 데이터 구조와 연산은 클래스와 메서드로 캡슐화
- **가독성 및 문서화**: 주요 클래스와 함수에 독스트링(Docstring) 및 주석 작성

### 4) 환경 및 제약 사항 (Constraints)
- GUI는 파이썬 내장 `tkinter`만 사용 (외부 GUI 라이브러리 설치 없이 실행)
- 모든 소스 파일은 동일한 루트 디렉토리 안에 위치하여 모듈 간 import가 원활하도록 구성

## 🗃 8. 데이터 설계

### 건강정보 레코드 구조

| 필드명 (Key) | 데이터 타입 | 설명 | 예시 값 |
|--------------|-------------|------|---------|
| `id` | String | 환자식별번호 (자동 생성) | `"P2026-0001"` |
| `name` | String | 사용자의 이름 | `"홍길동"` |
| `birth_year` | Integer | 출생 연도 | `1995` |
| `gender` | String | 성별 | `"남"` |
| `height` | Float | 키/신장 (단위: cm) | `175.0` |
| `weight` | Float | 체중 (단위: kg) | `72.5` |
| `bmi` | Float | 계산된 BMI 수치 (자동 산출 및 반올림) | `23.67` |
| `status` | String | 비만도 판정 결과 (저체중, 정상, 과체중, 비만) | `"과체중"` |

### 지원 파일 저장 형식

| 파일 형식 | 확장자 | 저장 구조 및 특징 | 주요 활용 목적 |
|-----------|--------|-------------------|----------------|
| JSON | `.json` | 딕셔너리 리스트 형태의 텍스트 구조, 사람이 읽기 쉽고 웹 표준과 호환 | 표준 데이터 저장 및 웹/외부 연동 |
| CSV | `.csv` | 쉼표로 구분된 텍스트 행 구조, 첫 행에 헤더 포함 | 엑셀 일괄 등록 및 표 형식 관리 |
| TXT | `.txt` | 커스텀 구분자로 연결된 한 줄 단위 문자열, 기본 파일 입출력으로 구현 | 가벼운 텍스트 기반 로그 및 단순 저장 |
| Pickle | `.pkl` | 파이썬 객체를 바이트 스트림으로 직렬화 | 프로그램 내부 객체 상태의 완벽한 보존 |

### 파일 형식 예제

**JSON**
```json
[
    {
        "id": "P2026-0001",
        "name": "홍길동",
        "birth_year": 1995,
        "gender": "남",
        "height": 175.0,
        "weight": 72.5,
        "bmi": 23.67,
        "status": "과체중"
    },
    {
        "id": "P2026-0002",
        "name": "김영희",
        "birth_year": 1998,
        "gender": "여",
        "height": 162.0,
        "weight": 52.0,
        "bmi": 19.81,
        "status": "정상"
    }
]
```

**CSV (utf-8)**
```csv
id,name,birth_year,gender,height,weight,bmi,status
P2026-0001,홍길동,1995,남,175.0,72.5,23.67,과체중
P2026-0002,김영희,1998,여,162.0,52.0,19.81,정상
```

**TXT (utf-8)**
```
P2026-0001,홍길동,1995,남,175.0,72.5,23.67,과체중
P2026-0002,김영희,1998,여,162.0,52.0,19.81,정상
```

**Pickle (이진 코드, 직접 보이지 않음)**
```python
[
    HealthRecord(id="P2026-0001", name="홍길동", height=175.0, weight=72.5),
    HealthRecord(id="P2026-0002", name="김영희", height=162.0, weight=52.0)

```
